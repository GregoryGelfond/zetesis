What the table consumer does

The library API separates immutable relation ownership, prepared indices and per-query result masks. A selection can outlive its table index while borrowing the original relation. Domain restrictions include typed constants, already-bound source values and repeated-variable aliases. Each probe derives fresh domains; it does not reuse a previous binding’s mask.

The completed eager consumer caches tables by signed predicate and canonical column scope. Increasing original row positions feed the same whole-row matcher, binding extension and authored-body checks used by indexed joins. Possible support remains distinct from model truth. Support-growth rounds and structural patterns keep indexed matching; this is an explicit scope boundary. Work, allocation and capacity failures remain grounding failures. The strategies can reach those limits at different points because their charged costs differ.
