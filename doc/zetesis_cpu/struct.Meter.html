Struct Meter

Expand description

One metered operation’s charged work, its local work limit and its view of control.

A meter exists only inside Cancellation::metered, which settles the operation’s outcome where it returns, so an operation that charges through a meter always gives a requested stop precedence over its resource refusals. A charge costs a boundary test and a limit test. The view of control is borrowed in place and read only at a boundary. The count sits between two padding words that are never read, so no paired load can combine it with another value: on aarch64 such a load cannot be forwarded from the previous charge’s pending store, and every charge in a per-node loop would wait for that store to retire.

A metered operation that runs another metered operation’s body passes it this meter. The nested work then counts toward this operation’s limit, the cadence of observations continues across the boundary, and this operation’s exit settles both. An operation of another arrangement, which observes control by its own rule and reports the work it charged, runs under Self::remaining and is counted by Self::absorb.

pub fn charge(&mut self) -> Result<(), ChargeError>

Charge one operation. Control is observed first when the operations charged so far complete a run of POLL_INTERVAL, so an operation that charges each of its steps observes it before its first step and at least once every POLL_INTERVAL steps. At the limit control is observed again before refusing, so a requested stop takes precedence over the work limit. An admitted charge counts the operation; a refused one does not.

§Errors

ChargeError::Stopped when an observation finds a requested stop or an expired deadline; otherwise ChargeError::WorkLimit at the limit.

pub const fn remaining(&self) -> u64

Operations the limit still admits: the work limit to give a nested operation of another arrangement, whose reported work Self::absorb then counts. The count never exceeds the limit (an admitted charge stops at it, and an absorb counts at most up to it), so this never underflows.

Source

pub fn absorb(&mut self, nested: u64) -> Result<(), ChargeError>

Count the operations a nested operation of another arrangement reports having charged under the allowance Self::remaining gave it. That operation observed control by its own rule; this meter’s cadence resumes from the new count, so its next observation follows within POLL_INTERVAL charges.

§Errors

When nested exceeds the remaining allowance, the nested operation overran the limit it was given. Its work was done, so the count reaches the limit and the operation can charge nothing more; then control is observed, as for a refused charge, and ChargeError::WorkLimit is reported otherwise.

pub fn poll(&self) -> Result<(), Stop>

Observe control now, as Cancellation::poll does, for example before a fallible reservation.

§Errors

Returns cancellation first, otherwise an expired deadline.
