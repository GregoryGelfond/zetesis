Actual formula GPU work and explicitly retained candidate results.

§adapter: String

Physical adapter name and native API selected during this invocation.

§completion: CompletionAccounting

Bounded batch completion accounting; scalar cursor execution has no record.

§gpu_limits: Option<FormulaDeviceLimits>

Effective general propagation limits, absent for CPU and tight support.

§gpu_residuals: Option<FormulaResidualStatistics>

Decoded residual reasons for the general GPU primitive. Absent for CPU and tight-support execution; distinct from committed cpu_residuals.

§gpu_residual_handovers: Option<ResidualHandoverStatistics>

Exact handover attempt accounting on the general GPU route.

§tight_work_per_candidate: Option<u64>

Tight-support work ceiling per candidate. Present only for that device primitive; propagation sweep limits do not apply to a support scan.

§gpu_scheduled_work: Option<u64>

Work of submitted tight batches, including unreturned ones: what a validated readback reports performed, or else the submission’s reservation, each candidate’s allowance for the routes it may take. Propagation has candidate-dependent work and leaves this absent.

§gpu_tight_routes: Option<TightRouteStatistics>

Decoded tight-support slots by route; absent before the first decoded tight batch and for other primitives.

§gpu_tight_updates: Option<TightUpdateStatistics>

The tight-support update route’s steady-state availability, or the last decoded batch’s while none has held reuse authority; absent before the first decoded tight batch and for other primitives.

§gpu_submitted_batches: u64

Batches actually submitted, including submissions without a decoded result.

§gpu_submitted_candidates: u64

Candidate worlds actually submitted, including unreturned results.

§gpu_batches: u64

Successfully dispatched and decoded GPU batches: device submissions, of which one candidate slate can take several.

§gpu_slates: u64

Candidate slates a GPU formula session committed with at least one candidate. A slate is the candidates the stream proposes together for one membership check and commit; the device checks it in one or more submissions. Zero for CPU routes.

§gpu_largest_slate: Option<usize>

The largest committed slate’s candidate count: at most the batch size under fixed batching, possibly more under adaptive batching. Absent before the first commit and for CPU routes.

§gpu_slate_resets: u64

Selections that returned adaptive slates to the batch size because the previous slate’s answers tightened the objective bound. Every such selection counts, including one already at the batch size and the session’s last selection, so a program reports one reset per slate whose answers installed a bound. Always zero under fixed batching and for CPU routes.

§gpu_lookahead_slates: u64

Slates a GPU enumeration proposed while their predecessor’s last submission was checked on the device. Zero for optimizing searches and for CPU routes.

§gpu_lookahead: Option<GpuLookahead>

The last decision on proposing a slate ahead: engaged, or declined with its reason, so a run shows why it stayed serial. Absent for CPU routes and before a GPU session’s first slate.

§gpu_lookahead_device_ns: u64

Device compute of the submissions checked while the host proposed the next slate, in nanoseconds: the measured intervals of Self::gpu_compute_timing that belong to those submissions, each paired with its submission’s finish wait in Self::gpu_lookahead_finish_wait_ns.

§gpu_lookahead_finish_wait_ns: u64

The finish’s waits on the same submissions, in nanoseconds: each from the end of the production run beside it to its observed completion, before its readback is mapped and decoded. The device time hidden behind production is the difference of the two paired sums, Self::gpu_lookahead_device_ns less this, over the overlapped submissions with a measured interval.

§gpu_lookahead_unmeasured: u64

Overlapped submissions whose interval the timer refused or never resolved. Neither paired sum includes them, so the hidden time covers only the submissions measured; zero for CPU routes.

§first_answer_ns: Option<u64>

Elapsed time from the device execution’s construction to the release of its first answer, in nanoseconds; reported, never a criterion. Absent before the first answer and for CPU routes.

§gpu_candidates: u64

Candidate worlds returned by successful GPU dispatches.

§gpu_work: u64

Charged primitive work from successfully decoded results; not time or GPU instruction count. Work in an interrupted unreturned batch is unknown.

§gpu_rounds: u64

Sum of completed per-candidate propagation sweeps in decoded results. Sweeps in an interrupted unreturned batch are unknown.

§cpu_residuals: u64

Committed candidates completed by exact native CPU residual search.

§gpu_decided: u64

Successfully committed candidates decided by the selected GPU primitive.

§pending_candidates: usize

Proposed candidates whose membership has not been committed.

§queued_models: usize

Verified stable interpretations still queued before scoring/output.

§peak_accounted_bytes: u64

Conservative peak authored allocation accounting reported by the device API.

§gpu_workgroup_size: Option<u32>

The workgroup size, in invocations per candidate, that the decoded device batches dispatched; absent before the first decoded batch. One value describes the solve: its execution owns one oracle checking one theory instance, whose retained graph fixes the size.

§gpu_compute_timing: ComputeTiming

Optional device compute-pass time of the decoded batches, each reported once from its own interval: measured, unavailable, or unresolved while the execution has not settled or when its settlement could not read it. Separate from host-oracle, transfer, waiting and exact residual time; a settlement’s resolve-only submission is counted as a flush, not a batch.
