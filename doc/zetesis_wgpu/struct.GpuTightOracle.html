pub struct GpuTightOracle { /* private fields */ }
Expand description

Real-device original satisfaction and ranked producer support checking.

Takes a complete opaque TightPlan; never constructs an unchecked rank or relies on an incomplete lazy registry. Candidate generation, objectives and any witness-producing residual completion remain the caller’s responsibilities. A complete failed support scan also permits proof-based rejection by the support-necessity theorem; it publishes no concrete deletion witness. Every nonempty successful call executes the support kernel on the selected adapter. Ordinary solver dispatch selects this independent primitive only after preparing its complete certificate; no CPU fallback occurs here.

Native threshold and extremum-cut rows remain shared condition/value columns in the immutable transport; both original-truth checkers use the same portable limb arithmetic. No Boolean numeric expansion or optional-width feature is required. Work is linear in candidates times nodes, row occurrences, roots, producers and atoms. Each workgroup evaluates independent nodes of each dependency level across its workgroup size of invocations, by default the size the theory’s schedule fits (see crate::GpuWorkgroupSizing), then shares root/support scans. Pure chains and cold preparations without room for the additional schedule retain serial original-truth evaluation. Truth uses one word per node; candidate membership and producer support use one bit per atom, in separate world-major arrays. Heads sharing a support word use atomic OR by default. Grouped support instead visits each word’s producers sequentially in one invocation; this trades contention for an index and potentially uneven parallel work.

Successive batches of one theory and count may also update retained evaluations (see TightGpuLimits::min_update_candidates). The first such batch appends a readers index to the producer storage: for each node the connectives and numeric-row owners reading it, the heads of the producers whose body it is and the root positions holding it, and for each atom its atom nodes. Each candidate slot then retains the candidate it evaluated, its support counts per head, and its false-root and unsupported-atom sets, and re-evaluates in dependency-level order only the nodes a new candidate’s changed atoms reach. Shared graph and transport storage have explicit byte bounds. The oracle retains one shared theory handle and one exact transport shape, without cloning the caller’s certificate or storing its ranks.

pub const UPDATE_ENGAGEMENT_STRIDES: u64 = update::ENGAGEMENT_STRIDES

Workgroup strides per dependency level that dense evaluation of a resident schedule must take, on average, at its dispatched workgroup size before the update route engages: before the theory builds the route’s readers index. Narrower schedules report TightGpuUpdateUnavailable::NarrowSchedule.

An execution choice that changes no verdict, calibrated by measurement on an Apple M4 Pro GPU under Metal: the factor covers the change patterns measured there, their per-level chains included, scattered changes and clustered changes of up to 64 atoms with one reader per input. Another device or backend can break even at a different factor. The choice is asymmetric: a declined schedule keeps dense evaluation, so a factor set high only forgoes gains, while one set low slows the schedules it engages. A change beyond those patterns whose critical path makes an engaged update dearer than dense evaluation, such as one reaching many nodes of one queued word, is the runtime guard’s: it compares each batch’s slowest update path with dense evaluation’s and declines the route for a few batches at a time (TightGpuUpdateUnavailable::GuardDeclined). The factor still decides whether a theory builds the index at all, which spares narrow theories the index, the state and every losing probe, and covers the update’s extra synchronization, which the guard cannot see.

Create a device with an explicit producer-support construction policy. The policy remains fixed for the oracle’s lifetime. pub const fn reported_compute_time(&self) -> Option<BatchComputeTime>

The compute-pass time of the batch this oracle’s latest call consumed.

Under enabled timing, a submitting call that completes reports the batch completed by the previous submitting call, from that batch’s own interval; its own batch’s interval is read by the next submitting call or by Self::flush_compute_time. A call that fails after submission reports the previous batch unavailable, abandons its own and retires the timer, so the next timed batch starts a fresh one. The flush reports the batch it resolved, and Self::clear_residency reports a discarded unresolved batch unavailable. Under unsupported timing each completing call reports its own batch unavailable; disabled timing reports nothing. None when the latest call consumed no batch: every call clears it at its start, including empty and refused calls. A measured duration is never zero and excludes host packing, uploads, readback and waits.

pub fn flush_compute_time( &mut self, timeout: Duration, cancellation: &Cancellation, ) -> Result<(), GpuError>

Resolve the unresolved batch’s interval with one resolve-only submission.

Returns at once, with no report, when no batch is unresolved. Otherwise a zero timeout is refused; the context lease is taken, and Busy submits nothing; cancellation and context health are then checked once, and a stop or an unhealthy context submits nothing. Each refusal leaves the batch unresolved and a healthy context reusable. The flush then waits at most timeout for its submission, polling no control. On observed completion the batch is reported, measured or unavailable, and the context stays reusable. A timeout or a mapping, device or scope failure reports it unavailable, retires the timer and invalidates the context, as for any submission whose completion is unknown or faulted. The flush allocates nothing and downloads 16 bytes; batch statistics and Self::activity exclude it.

§Errors

Returns the refusals and failures above.

pub fn check_batch( &mut self, certificate: &TightPlan, candidates: &[Interpretation], limits: TightGpuLimits, cancellation: &Cancellation, ) -> Result<Vec<TightGpuCheck>, TightGpuError>

Check complete original truth and support for every ordered occurrence. Repeated interpretations remain repeated results. The first false root follows original root-list order; unsupported atoms use ascending order.

Checks control and health even for an empty batch, then returns no results without charging storage/work or dispatching. On nonempty calls, clones of one Theory reuse immutable storage; independent equal theories do not. Every admitted TightPlan canonically extracts producers from all original roots, independently of the particular valid ranks. Thus theory identity is sufficient for this producer cache; arbitrary supplied producers are never accepted. Transport is replaced when candidate count changes. Original truth may reuse unchanged dependencies from a wholly successful prior batch with that same subject/count. Every root and producer remains covered: the complete and dense routes check each of them, and the update route maintains their support counts and the false-root and unsupported sets. Both reuse routes are optional: change detection runs only when its work allowance fits, otherwise the complete evaluation runs without new storage; the update route runs only on a schedule wide enough to engage it, when its per-slot state and its reservation are admitted and while the runtime guard has not declined it after a batch whose slowest update’s critical path exceeded dense evaluation’s, otherwise the dense routes run. A later call that cannot admit a held state releases it and keeps its truth and result authority; a built readers index stays resident and accounted, like a retained schedule. Host upload words reuse initialized scratch for that same subject/count. Their actual capacity is charged, and an oversized optional allocation is replaced when a smaller allowance fits fresh storage. Replacement drops old scratch before cold preparation; explicit clearing releases it too.

§Errors

Returns no partial result vector on foreign identity, capacity, work, allocation, cancellation, deadline, validation, device or readback failure. Host preparation refusals leave the oracle reusable. Failures after device allocation/submission invalidate the entire context, and a fresh context is required before retrying, except a cancellation or deadline stop whose submission was observed to complete and whose readback was mapped and released: that leaves the context reusable, as crate::GpuContext documents. Busy contention submits no work and permits retry. Cancellation is polled during packing, waiting, decoding and before returning. A tighter work limit can bypass a resident dependency schedule. Its bytes remain charged: a smaller byte limit may refuse that retained layout. Requested device timing charges 96 bytes to the same batch allowance: the oracle’s query slots, two resolve buffers and flush readback, and the readback tail of the batch’s transport. It never changes logical verdicts. Under fitted sizing, the first call that dispatches a size compiles its pipeline. A failure to compile it is reported before any dispatch and invalidates the context; the size stays uncompiled, and no theory stays resident, because only a freshly prepared theory can need a size first and its cold preparation released the previous one. Each size has two kernels: one with the update route, which runs exactly the batches that allow it, and one without, which runs every other batch. A freshly prepared theory’s first batch never allows the route, so the kernel without it is the one a size needs first. The kernel with the route is compiled with the oracle under fixed sizing, and otherwise at the first batch that allows it, which only a resident theory reaches. A failure to compile it there also invalidates the context; the theory stays resident, and its retained truth is invalidated, as after every failed call.

pub fn check_prefix<'a>( &mut self, certificate: &'a TightPlan, candidates: &'a [Interpretation], limits: TightGpuLimits, cancellation: &Cancellation, ) -> Result<CheckedBatch<'a, TightGpuCheck>, TightGpuError>

Check the largest nonempty prefix admitted by the prepared tight layout.

The input slice and max_candidates both cap the count. Cold certificate packing occurs once, then the existing checked layout selects the largest count for that schedule. The returned receipt borrows exactly the checked prefix in its original order. Empty input still observes control and context health. Statistics and submission activity name the actual prefix.

§Errors

Preserves Self::check_batch’s typed failures and returns no partial checks. A one-candidate capacity or mandatory-work refusal remains an error. Allocation, cancellation and device faults never authorize retry at a smaller count or CPU fallback.

pub fn prepare<'o>( &'o mut self, certificate: &TightPlan, slate: SlateRef<'_>, offset: usize, limits: TightGpuLimits, cancellation: &Cancellation, ) -> Result<PreparedTightSubmission<'o>, TightGpuError>

Prepare the next submission of slate: admit the largest nonempty prefix of its candidates from offset on, as Self::check_prefix admits a prefix, pack it into this oracle’s reused upload storage, and plan it: reuse authority, the update route’s engagement under the runtime guard, the kernel and the epoch. Nothing is submitted.

The returned submission holds this oracle’s mutable borrow until a check consumes it, so no other operation on the oracle, and no second preparation, can run between the plan and its check: the state it was planned from is the state it runs on. Dropping it submits nothing and releases the borrow; any retained state its preparation replaced stays released, and the next check prepares again. The context’s lease is taken by the check, not here, and this polls control and context health before preparing.

§Errors

Refuses a slate whose theory is not the certificate’s instance, an offset that leaves no candidate, and every refusal and failure of Self::check_prefix’s preparation, which leaves the oracle reusable and its retained truth invalidated, as after every failed call.
