Struct PreparedFormulaSubmission

pub struct PreparedFormulaSubmission<'o> { /* private fields */ }
Expand description

One submission of a slate that a GpuFormulaOracle admitted, packed and planned but has not submitted (GpuFormulaOracle::prepare).

It holds its oracle’s mutable borrow until Self::check or Self::check_overlapping consumes it, so what is resident and the epoch are those its check runs on. It carries copies of its slate’s identity, its offset and its count, and no borrow of the slate’s candidates, so the slate’s stream can be borrowed again while it runs. A second preparation cannot begin while one exists:

ⓘ
let first = oracle.prepare(slate, 0, FormulaLimits::default(), control);
let second = oracle.prepare(slate, 0, FormulaLimits::default(), control);
drop((first, second));

Nor can any other operation on the oracle run between a preparation and its check:

ⓘ
let prepared = oracle.prepare(slate, 0, FormulaLimits::default(), control).unwrap();
oracle.clear_residency();
let _ = prepared.check(control);

And a prepared submission is checked only by its own oracle: the oracle has no public operation that takes a prepared submission, so one prepared elsewhere has nowhere to go.

ⓘ
let prepared = one.prepare(slate, 0, FormulaLimits::default(), control).unwrap();
let _ = other.propagate(prepared, control);

One after the other, they compile:

let first = oracle.prepare(slate, 0, FormulaLimits::default(), control).unwrap();
let _ = first.check(control);
let second = oracle.prepare(slate, 0, FormulaLimits::default(), control).unwrap();
let (_, during) = second.check_overlapping(control, || 1);
assert_eq!(during, Some(1));

pub fn check_overlapping<R>( self, cancellation: &Cancellation, during: impl FnOnce() -> R, ) -> (Result<CheckedSlate<FormulaCheck>, GpuError>, Option<R>)

Submit the prepared batch, run during while the device checks it, then finish: wait for the submission, map, decode and settle it. One submission is in flight while during runs, and none when this returns; nothing this returns names the submission.

The context’s lease is held from before the submission to the finish, including during, so another operation on the shared context is refused with Busy meanwhile, and an operation on the same context inside during is refused too. The error scopes close right after the submission, before during. When the control has fired by the time during returns, the finish observes the submission’s completion without polling the control, within the batch’s timeout, so a completed and released readback leaves the context reusable, and the stop is reported without decoding. A panic in during unwinds through this operation and invalidates the context, since its submission’s completion is then unobserved.

Returns the check’s outcome and during’s result. A successful outcome’s receipt carries the finish’s wait after during (CheckedSlate::finish_wait). The result is absent only when the check failed before submitting, in which case during did not run.
