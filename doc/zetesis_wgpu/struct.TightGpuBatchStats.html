Resource evidence for the last successful nonempty batch.

Fields (Non-exhaustive)§

§theory_uploaded: bool

A different immutable theory required graph upload.

§transport_allocated: bool

Exact candidate-count transport was allocated or replaced.

§resident_theory_bytes: u64

Requested immutable header/operand, root and producer buffer bytes, with padding; the producer buffer includes a built readers index.

§resident_transport_bytes: u64

Requested uniform, candidate, truth, support, result and readback bytes, and the per-slot update state once admitted: bound when the update route is allowed, and otherwise allocated but unbound, on the kernel without the update route.

§accounted_bytes: u64

Conservative authored payload checked against the batch byte ceiling.

§candidates: u64

Fully checked input occurrences, preserving repetitions.

§work: u64

Sum of the operations each candidate’s route performed.

§dispatches: u64

Actual compute submissions; one for this nonempty successful batch.

§truth_levels: u32

Dependency levels evaluated cooperatively; zero selects serial original truth.

§workgroup_size: u32

The workgroup size dispatched, in invocations per candidate: the fixed size, or the size the theory’s dependency schedule fits.

§original_truth_reused: bool

A wholly successful same-subject/count batch supplied original truth. This selects change detection; it does not assert that any gate was skipped.

§routes: TightGpuRoutes

Candidate slots per route.

§nodes_evaluated: u64

Nodes re-evaluated by update-route slots, summed over the batch.

§update_critical_path: u64

The largest critical path among the batch’s update slots (see TightGpuCheck::critical_path), or zero without update slots: the runtime guard’s measure of the update route.

§dense_critical_path: u64

Dense reuse’s least critical path for one candidate at the dispatched workgroup size, by the same cost table as an update’s: each dependency level’s and each scan’s busiest invocation, summed, where every candidate-dependent cost takes its least. The runtime guard declines the route after a batch whose update_critical_path exceeds it. Zero for a schedule the update route does not engage.

§updates: TightGpuUpdates

Whether the update route was available to this batch, and why not.

§uploaded_bytes: u64

Authored initialized/write-buffer payload, not measured bus traffic, including the rebuilt producer buffer of a batch that builds the index.

§downloaded_bytes: u64

Successfully decoded readback payload, not measured bus traffic.
