# Finite bindings and the logical value carrier

The present foundation combines independent closed integer lower/upper comparisons into a finite range for an otherwise unbound variable. Strict endpoints are widened before testing emptiness; machine endpoints cannot wrap a reversed interval into a nonempty one. Every original comparison remains in the complete body guard. A single default-negated comparison supplies no generator. Dynamic inequality endpoints and chains with several unresolved variables remain outside this slice.

One positive or double-default-negated flat tuple equality can supply scalar bindings only when its whole opposite tuple is already bound. The original tuple equality remains, so repeated targets and incompatible components still reject a row. In particular `(X,Y)=(Y,1)`, `(X,Y)=(1,X)` and `(X,1)=(2,Y)` cannot bootstrap their own safety; adding an independent positive binder may make them safe. Double-default-negated equality to one finite interval also proposes a range, then checks the retained complete membership guard. Rule, choice, aggregate and conditional-local scopes keep their existing boundaries.

The finite mathematical transformer in `proofs/Zetesis/FiniteBindings.lean` is a separate specification: fold lower/upper bounds into a supplied finite interval, enumerate it, and apply a complete total Boolean guard. Its stated contract relates that algorithm to an independent finite filtering specification and arbitrary unchanged Ferraris formula instances for every original/frozen interpretation. Source recognition, tuple safety, Rust scheduling, arithmetic, support completion and runtime resource accounting are not established by this law. The source compiler/runtime remains explicitly unproved.

## Structural carrier and remaining binding work

The original finite-binding slice retained scalar `Value`/`Term`/`AtomPattern` identity. The subsequent [closed structural values](closed-structural-values.md) implementation adds bounded complete functions and tuples, including whole-variable copying. Closed tuple comparisons now compare complete values. Variable-containing flat tuple equality retains its existing finite binding planner. No sibling, parser pin or semantic atom encoding changes.

The implemented carrier is shared by source evaluation, whole-value positive matching, aggregate whole-tuple keys, objective keys, signed atom identity and observation. Constructor pattern extraction and variable-containing generation are the next separate obligations. Pattern extraction may bind variables only from finite existing values or explicitly bounded construction; recursive constructors need a terminating finite construction/coverage policy, not a global implicit term universe.

Admission must preflight depth/node/payload bounds before recursion, cloning, hashing or ordered comparison. Use iterative operations on hostile depth and charge matching/construction work and retained identity bytes. Stable-model subset relations and blocking continue to use complete semantic atoms; structural interning cannot merge values merely because their displays coincide. Signed predicate identity remains separate from a numeric minus inside an argument.

The closed carrier now supplies a common contract for these consumers. Extending it to constructor patterns still needs exact binding and finite candidate-coverage contracts. Existing Lean scalar/subset laws do not supply the missing source/Rust representation bridge.

Current source admission has no caller `Control` parameter; this slice preserves typed work/width/expansion stops and does not claim a newly implemented cancellation API.
