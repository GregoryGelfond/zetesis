# Boolean heads, objective values and conditional witnesses

This tranche starts from qualified checkpoint `363830b`. Its purpose is to close three
bounded source-language gaps while retaining exact acceptance through the original
program's Ferraris reduct. It does not establish full clingo compatibility.

| Capability | First deliverable | Boundary |
|---|---|---|
| Boolean heads | Boolean singleton heads, all default-negation signs and Boolean disjuncts under already admitted conditions | Preserve safety, original source diagnostics and complete sibling admission before simplification. Boolean operands supply no atoms or support. |
| Objective values | Closed nonnumeric literal weights; then a justified bounded extrema-presence extension | Separate possible value proposals, completed priority presence and model-relative contributions. Do not prune proposals to reproduce reference metadata. |
| Conditional witnesses | Positive local witness extraction combined with evaluated arguments | Capture finite existing rows, evaluate only bound inputs and retain complete consequent atoms. Do not repair outer safety or invert arithmetic. |
| Feature composition | Shared interfaces, proof registry and qualification | Preserve library-first boundaries, source identity, full model/cost contracts and truthful bounded outcomes. |

Head operands, lowering and support traversal share one representation. Objective
atom access must preserve both signed dependencies and positive-producer
distinctions. Weight admission and presence evidence remain separate from local
consequent compilation and matching. Shared methods must preserve these
distinctions without duplicating representations.

The objective work is staged. Literal nonnumeric weights already have a natural
resolved-value interpretation in the evaluator; admission must preserve empty
costs versus present numeric-zero priorities. The next stage must establish a
constructive presence contract for an explicit finite profile before removing
any mixed-extrema guard. Existing reference counterexamples, including cases
where impossible contributing values still leave a priority present, constrain
that contract. A new refusal alone is not closure. Broader filtered producers,
objective-dependent heads and dynamic priorities retain their obligations.

The witness slice targets cases such as
`{p(1,2);p(2,4)}. q :- p(X,X+1):#true.`. Local extracted names cannot establish
condition or outer-rule safety. Arithmetic checks consume matched values and
retain their source failure and resource contracts. Negative anonymous witnesses,
arithmetic inversion and new pool/interval contexts remain separate work.

Each slice includes unchanged original sources compared with clingo, independent
original/frozen formula checks, meaningful failure controls, bounded-work checks
and the applicable Lean semantic laws. The laws belong in the audited registry;
interactions require checks in prepared library sessions and ordinary CLI
execution. Semantic theorems do not by themselves verify Rust or WGSL execution.

Qualification requires portable and external-oracle gates, both independent 91% line
coverage floors, exact physical Metal qualification, current documentation and
the 94-case corpus plus selected upstream replay. Keep source and build identities
separate. Record actual routes and incomplete outcomes; neither an ignored
device test nor a resource stop is a successful complete solve.

Retain performance regression checks and record reusable optimization openings.
Broad optimization implementation follows source-language closure. No comparative
speedup claim follows from incidental test timings. Rust `@` execution is a later
explicit milestone; its planned haversine example is recorded in
[the function contract](rust-functions.md).

## Following this checkpoint

The next tranche now prioritizes [semantic architecture and library alignment](semantic-architecture-tranche.md).
The following language slices remain a recorded backlog: numeric weighted-head
aliases and bounded conditional disjuncts. Both remain unimplemented at this checkpoint.

Weighted heads can reuse the separation between atom permission and complete-tuple
activity already established for count heads. Start with signed numeric `#sum`
and nonnegative numeric `#sum+`; qualify numeric extrema separately. Both alias
directions, complete-key coalescing, zero-weight permission, recursive eligibility
and exact resource ceilings need original/clingo and arbitrary frozen-reduct
checks. Removing the existing guard alone would not establish that contract.

Conditional disjuncts need an explicit scoped alternative and eligibility
representation. A first slice can consume safely bound arguments and existing
finite positive conditions without adding inverse arithmetic or objective
consumers. Empty head families, inactive conditions, signed siblings, recursion
and complete validation before simplification are essential controls. The Lean
contract must distinguish existential head alternatives from universal body
conditionals and preserve eligibility under the reduct.

Broader objective producers and dynamic priorities need a separate foundation
task. The flat certificate does not justify filtered or multiple producers, and
variable priorities cross the existing fixed-priority template interface.
Objective-dependent head guards should remain until their own completed-presence
contracts preserve absent costs, numeric-zero priorities, global keys and ties.
Language coverage can expose later optimization opportunities; it does not by
itself demonstrate a performance benefit.
